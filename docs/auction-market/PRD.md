# AuctionMarket · 第一阶段 PRD（研究与数据验证）

## 业务问题

针对国服 Classic Era/Hardcore「硬核服」联盟，采集器提供可编辑的物品清单。初始清单包括黑莲花、五种黑莲花合剂及石鳞鱼油；用户可填写国服物品名称和物品 ID 增项，也可移除不再关注的项目。

游戏内插件只负责按统一规则采集并保存 AH 原始挂单快照，不计算价格趋势、市场库存或相关性；分析由独立的数据平台负责。用户每次明确选择一个清单物品后才发起查询，该物品的分页会在遵守客户端冷却的前提下自动连续采集；不会自动切换清单项目。

1. AH 可见流通量、日新增上架区间以及卖家角色集中度是多少？
2. 大卖家角色如何补货和调整报价？上涨后的 1/3/7 天市场深度是否恢复？
3. 依据**待核实**的游戏机制、地图、独立位面刷新与实际利用率，理论日产能可能在哪个区间？
4. 黑莲花价格/供应变化对 7881 元/1000G 参考报价是否有独立的样本外预测增益？不能混淆相关性与因果。
5. 可观察市场规模、未观察部分、数据质量和资本需求的上下限是多少？

不提供市场操纵或自动交易工具；研究结果可能得出“数据不足”或“无统计证据”。

## 数据源和采样

- WoW 内用户点击清单物品触发 AH 查询，自动逐页采集该物品；每个物品都采用同一记录字段，并以国服简体中文名称及物品 ID 校验返回结果。清单可在游戏内增加或移除项目。严禁模拟点击和绕过 API 冷却。实际支持的 AH API、卖家字段、自动翻页和各清单项目都需在客户端本机测试。
- 原始快照：`scan_id`、`observed_at`、`realm`、`faction`、`client_build`、`query`、`page`、`count`、`total`、`rows`、`complete`、`quality`；每条行保留 `item_id`、`item_name`、`quantity`、`buyout_copper`、`seller_character`、可选 `time_left_bucket`（客户端可用时）及相应缺失标记。剩余时间仅为客户端分档，不是精确挂单时间；需真实客户端验证覆盖率。
- 7881：用户链接 `https://h5.7881.com/pages/list/index-new?gameId=G6242&gtId=&extId=&extValue=&t=1792278012107`。先核实分类与平台使用限制，无法合规采集时导入手工 CSV，保存报价时间、深度、币种和手续费信息。
- 社区或游戏机制资料：每个机制参数标记出处/日期，保留产能上下界，未经验证不硬编码某个地图刷新率。
- 用户历史观察：2–3 位面约 ¥40/1000G；10 位面约 ¥120/1000G；7 位面约 ¥64/1000G。**仅为待核实报价观察**，没有精确日期，不用于无时间戳训练集。

## 观测与推断边界

- AH 当前挂单 ≠ 玩家全部库存；挂单消失 ≠ 成交；反复上架 ≠ 新采集。
- 不同卖家角色不等于不同真人；同一真人可能有多个角色；不将时间规律或卖家集中度当成工作室身份的证据。
- 扫描不完整时不能统计市场总量，应在 Web 显示覆盖度、重复扫描、卖家可见率和缺失比例。
- `getAll`/常规查询限流由游戏 API 决定，客户端禁止时不发请求。

## 模型设计

第一版优先稳定数据观测和时间序列基线：
- `listing_value_copper = sum(buyout_copper)` 对全部可买断且价格>0的行计算；记录不支持买断的行占比。
- `TopN` 和 `HHI` 以**扫描当时的可见挂单数量**计算，仅当可用卖家名称比例满足阈值时展示。
- 以 seller-character、item、scan 组合建立可见供应时间序列；在没有稳定拍卖 ID 时不试图精确识别哪朵黑莲花被卖出。
- 联合 `observed_at`、卖家角色与时限档位，最多估计挂单首次/末次可见时间和粗略到期窗口；不能据此精确推断上架时刻、真实账号、成交/撤单/流拍原因。
- 理论产能模型：`layers × hourly_spawn_min/max × hours × capture_rate_min/max`，所有系数由带来源的情景输入，不作为真实产量。
- 预测基线：naive、季节性 naive、岭回归或 ElasticNet（样本满足条件时）；严格时间递进训练/测试、滞后特征、模型与基线比较，报告 MAE、RMSE、方向准确率及误差区间。样本不足明确拒绝出预测。
- 金价联动研究必须单独控制时间趋势、位面变动、活跃度与金币市场报价深度；只报告增量预测能力，不把关联结论写成价格影响因果。

## 开发验收

A. 保留原 WOW Keyword Monitor 所有文件内容原样，TOC 和 SavedVariables 名称不变，有安装/回滚指引；
B. 手动采集清单中的 AH 页面并保存于新的 SavedVariables；国服实测报告说明各项目 API 可用性与卖家缺失率；
C. Mac 能解析 SavedVariables 并生成可复验的 JSON；后端可靠接受并去重存储；
D. Web/CLI 能显示可观察的黑莲花挂单量和集中度，并标记不足以推断工作室规模的情况；
E. 7881 用有明确时戳的手工导入打通数据模型，未验证的爬取不实现。
