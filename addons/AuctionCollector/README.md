# AuctionCollector · 0.2.2-alpha

独立 WoW 插件，只在玩家点击按钮或输入命令时请求拍卖行数据。安装路径为 `Interface/AddOns/AuctionCollector/`，和 `WOW_keywordmonitor` 共存，不共用 SavedVariables。

## 🎮 游戏内状态面板

**输入 `/ac` 即可打开/关闭**。打开拍卖师界面时，状态面板也会自动弹出；窗口可拖动、右上角可关闭。

| 状态 | 面板颜色 | 含义 |
|---|---|---|
| 尚无扫描记录 | 灰色 | 没有从 SavedVariables 读回数据 |
| 正在等待 | 黄色 | 已人工请求扫描，等待 AH 回调或卖家名称解析；不代表已采集成功 |
| 扫描成功 · 数据在内存中 | 黄色 | 已收到挂单数据，但 **尚未写入 Mac 文件** |
| 已从 SavedVariables 存档读回 | 绿色 | `/reload` 或再次登录后，插件已读取上次写入的数据 |
| 查询返回 0 条 | 黄色 | 显示空结果，但因 Legacy 事件无请求标识而不写入扫描记录；不证明全服无货 |
| 查询失败、API 不可用、查询超时 | 红色 | 本次没有可用数据或请求未完成 |

面板持续显示：**本次新采集页数、上次登录/重载时读回存档页数、当前缓存页数、最后扫描时间、当前页挂单条数及数量、卖家名称可用率、剩余时限档位可用率、查询耗时和最近三次扫描记录**。任一请求失败会在面板中显示原因。

Legacy API 首次返回时可能尚未解析部分卖家名称。插件会等最多 2 秒，并在列表更新事件到达时重读当前页；等待期间不会再次发送拍卖行查询。超时仍缺失的卖家会保留价格与数量数据，但将该页标记为 `complete=false` 和 `seller_resolution_timed_out=true`，不能用于卖家集中度分析。

若客户端提供 `GetAuctionItemTimeLeft`，插件会逐条保存 `time_left_bucket`（客户端返回的 1–4 档剩余时限类别），并记录 API 可用性和缺失数。**这是粗粒度的剩余时间档位，不是精确倒计时或挂单时间**；只能在重复扫描中辅助估算挂单年龄/时段。卖家字段是角色名，可用于追踪同一角色在可见分页中的重复挂单，不代表同一账号或真人。当前国服客户端是否提供该字段，需用本版本实际扫描确认。

### 正确的采集—落盘验证流程

1. 登录游戏、打开拍卖行，此时面板会自动出现。也可输入 `/ac`。
2. 点击 **扫描黑莲花**。面板先显示「等待返回」，收到 AH 结果后显示「已采集 N 条（内存）」。必须确认挂单条数而不是仅看「已发送」。
3. 等待查询返回期间不要在 AH 中发起其他搜索。Legacy 列表更新事件不带请求 ID；若当前结果中的物品名与本次查询不符，插件会拒绝保存。其他搜索若恰好查询相同物品，客户端仍无法证明分页来自哪次请求，因此应等待面板确认后再继续操作。
4. 若需完整查询结果，手动点击 **扫描下一页**。各页单独保存；请注意查询冷却及其他拍卖助手可能造成的冲突。
5. 点击 **写盘并重载**，或正常退出游戏。该按钮等价于用户主动执行 `/reload`，不会自动扫 AH。
6. 重新加载后面板应显示绿色「**已从存档读回 N 页扫描数据**」。这证明插件读回了 SavedVariables；**不代表已上传 Azure**。
7. 若需要在 macOS 文件层面确认，检查 `World of Warcraft/_classic_era_/WTF/Account/<账号>/SavedVariables/AuctionCollector.lua` 中是否存在 `AuctionCollectorDB`、`scans` 和 `scan_id`。再运行 `apps/mac-sync/sync.py --dry-run` 检查解析条目。

**重要：WoW 插件自身无法直接读取或确认 Mac 文件系统上的文件，因此只会显示「数据在内存中」与「重载时从 SavedVariables 读回」，不会在首次扫描后冒充已落盘。**

## 其他命令

- `/ac` 或 `/ac ui`：显示或隐藏状态面板
- `/ac probe`：查看 Legacy API、C_AuctionHouse 是否存在、服务器、阵营及客户端 build
- `/ac lotus`：人工扫描黑莲花第一页（Legacy `QueryAuctionItems`）
- `/ac next`：人工查询下一页，不自动翻页
- `/ac page 2`：手动查询指定页
- `/ac status`：在聊天框和面板展示采集/存档状态

SavedVariables 名称为 `AuctionCollectorDB`，最多保留最近 80 次分页快照；在云端导出前过多扫描可能让旧数据被覆盖，请及时同步。

## 实测状态与限制

真实国服客户端已验证 Classic Legacy 查询能返回黑莲花物品 ID、数量和价格；0.2.1-alpha 的一次复测中 31/31 条记录均解析出卖家名。0.2.2-alpha 新增剩余时限档位采集，**尚待真实国服客户端验证 API 可用性和返回字段质量**。

当前采集器仍仅支持 Classic Legacy `QueryAuctionItems` / `GetAuctionItemInfo`；剩余时限接口是可选字段。若客户端仅有新版 `C_AuctionHouse`，面板会提示 API 不兼容，而非声称扫描成功。卖家名称仍取决于游戏 API 是否返回；若超时未解析，快照可用于价格和可见数量分析，但不可用于卖家集中度分析。即使卖家名和时限档位齐全，也只能估算同一角色挂单持续出现的时段；挂单消失不能区分成交、撤单或到期。拍卖行第一页或其他单个分页 **不是全服市场库存**，也不能根据角色身份判断工作室。

如果面板显示 0 条，可能是查询结果确实为空、API 不兼容、缓存未加载、其他 AH 插件干扰或扫描覆盖不足；请记录 `/ac probe` 输出以及面板最后一次扫描信息。

无自动买卖、后台自动查询、模拟点击、反 AFK、绕过查询限速或对游戏内存的读取。
